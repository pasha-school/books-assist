# Rule: incremental-updates

Граф знаний растёт по главам. Агент **никогда не перезаписывает** заметки целиком — только дополняет.

## Алгоритм для каждой сущности

1. **Проверь, существует ли файл** по правилам неймига ([`naming.md`](naming.md)).
2. Если **не существует** → создай по шаблону из [`../templates/`](../templates/), заполни известные поля, остальное оставь пустым.
3. Если **существует** → читай frontmatter и тело, дополняй:
   - В `appears_in` — добавь новую главу (если ещё не там).
   - В `relations` — добавь новые связи (см. [`schema.md`](schema.md)). Существующие не трогай, даже если формулировка отличается, — лучше добавь дубликат с `confidence: low`, человек решит.
   - В тело заметки — секции `## Глава N` с фактами этой главы. Старые секции не редактируй.

## Что запрещено

- Удалять существующие frontmatter-поля.
- Переименовывать заметки (имя файла = идентификатор, на него уже ссылаются другие заметки).
- Менять `aliases`, `type`, `book` существующей заметки.
- Стирать пользовательские правки в теле заметки. Если непонятно, куда вставить — добавь в конец секцию `## Глава N (от агента)`.

## Идемпотентность

Повторный запуск разбора той же главы **не должен** плодить дубли:

- перед добавлением в `relations` проверь, нет ли уже точно такой пары `to+type`;
- перед добавлением в `appears_in` проверь, нет ли уже этой главы;
- перед созданием `event` ищи по `chapter + order` — если такой есть, обновляй его, а не создавай новый.
