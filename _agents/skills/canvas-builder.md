# Skill: canvas-builder

Генерация `.canvas`-файла — «карты главы» или «карты тома» для совместного просмотра с ребёнком через obsidian

## Когда применять

- «Сделай карту главы N».
- «Покажи всех персонажей и их связи на одной схеме».
- «Сделай схему событий тома».

## Формат файла

`.canvas` — обычный JSON в vault. Минимальная схема:

```json
{
  "nodes": [
    {
      "id": "ch-alice",
      "type": "file",
      "file": "Книги/Алиса в стране чудес/Персонажи/Алиса.md",
      "x": 0, "y": 0, "width": 260, "height": 100
    }
  ],
  "edges": [
    {
      "id": "e1",
      "fromNode": "ch-alice",
      "toNode": "ch-rabbit",
      "label": "встретила"
    }
  ]
}
```

**Все узлы-сущности должны быть `type: file` и ссылаться на реальную заметку в vault** (`Персонажи/...md`, `Места/...md`, `События/...md`, `index.md`). Не создавай `type: text` узлы вместо ссылок на персонажей/места/события — они «висят в воздухе» и не участвуют в графе.

Допустимый `type: text` — только для заголовков/легенд карты, если в vault действительно нет такой заметки.

**Группировка.** Используй `type: group` с `label`, чтобы визуально объединять связанных персонажей/места (например, «Род Троекурова», «Род Дубровского», «Ключевые события»). Группа — это просто прямоугольник с подписью, узлы внутри располагаются по координатам.

Полная спецификация: <https://jsoncanvas.org/spec/1.0/>.

## Алгоритм

### Шаг 1. Собрать данные

1. Узнай область: глава N / том / вся книга.
2. Соберай узлы:
   - **карта главы**: все `character` из `new_characters` главы + все `location` из `new_locations` + все `event` главы. Плюс уже известные персонажи, **участвующие в событиях** этой главы.
   - **карта книги** (`Карта.canvas`): все `character` и `location` книги + **только ключевые события**. Ключевое событие — это событие с `importance: критическая` (или `high`/«ключевое» по контексту, если поле отсутствует). Цель — не более ~0-1 ключевых событий на главу: поворотные точки сюжета, без проходных сцен, в крайних случаях 2.
   - **карта тома**: как «карта книги», но ограниченная томом.
3. Собери рёбра:
   - из `relations` персонажей → подпись = `type`;
   - персонаж ↔ событие (если в `participants`) → подпись = `участвует` (или роль: `инициатор`, `жертва`, `исполнитель` или иная — если она явно записана в событии);
   - событие ↔ место (если в `location`) → подпись = `место`.

### Шаг 2. Раскладка

Поскольку у агента нет графического движка, используй **сеточно-кластерную** раскладку:

- **По смыслу:** группируй узлы по сюжетным «лагерям» — например, для «Дубровского» это «Род Троекурова» (Троекуров, его слуги, его места) и «Род Дубровского» (Дубровский, его места). Внутри лагеря: персонажи сверху, их места — под ними.
- **События** располагай в отдельном ряду снизу, под обоими лагерями — так визуально видно, какое событие к кому относится.
- **Index книги** — узлом-«шапкой» по центру сверху, с рёбрами `главный герой` к ключевым персонажам.
- Используй `type: group` с подписями для визуального обрамления кластеров (см. выше).
- Между кластерами оставляй ~200–300 px свободного пространства.

Размеры узлов: `width: 260, height: 100` для персонажей и мест; `width: 320, height: 140` для событий и `index.md`.

Не пытайся делать force-directed раскладку «на глаз» — лучше предсказуемая сетка, человек подвинет руками.

### Шаг 3. Сохранение

Имя файла:

- карта главы → `Книги/<Название>/Главы/Глава-NN.canvas`
- карта книги → `Книги/<Название>/Карта.canvas` (один файл на книгу, обновляется инкрементально)
- карта тома → `Книги/<Название>/Карта-Том-<N>.canvas`

Перед записью **прочитай существующий файл**, если он есть, и сохрани там пользовательские координаты узлов по `id` — не сбрасывай ручную раскладку. Логика:

```
old_node_by_id = {n.id: n for n in old.nodes}
for new_node in new_nodes:
    if new_node.id in old_node_by_id:
        new_node.x = old_node_by_id[new_node.id].x
        new_node.y = old_node_by_id[new_node.id].y
```

### Шаг 4. id-нейминг (важно для идемпотентности)

- `character` → `c-<slug-имени>`
- `location` → `l-<slug-названия>`
- `event` → `e-<id-события-без-расширения>`
- ребро → `r-<from-id>--<type>--<to-id>` (детерминированно, чтобы повторный билд не плодил дубли)

`slug` — латинская/кириллическая «змейка» из имени с заменой пробелов на `-`, в нижнем регистре.

## Отчёт

После генерации сообщи: путь к canvas, число узлов и рёбер, сколько координат сохранено от предыдущей версии.

## Антипаттерны

- ❌ Наносить на карту главы персонажей, которые в этой главе **не** появляются.
- ❌ Перезаписывать canvas, не сохранив координаты пользовательских узлов.
- ❌ Использовать в `label` рёбра не из контролируемого словаря типов связей.
- ❌ Помещать на `Карта.canvas` все события подряд — карта книги должна оставаться читаемой. Только ключевые поворотные точки сюжета.
- ❌ Удалять с `Карта.canvas` ранее добавленные узлы при инкрементальном обновлении (характер/место уже виден — оставляем).
