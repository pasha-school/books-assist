# Skill: extract-chapter

Главный навык. Используется после прочтения каждой главы.

## Вход

- Текст главы (целиком или часть).
- Номер главы `N`.
- Путь к книге в vault: `Книги/<Название>/`.

## Обязательные правила

Перед началом прочитай:
- [`../rules/no-spoilers.md`](../rules/no-spoilers.md) — **никаких** фактов из будущих глав.
- [`../rules/incremental-updates.md`](../rules/incremental-updates.md) — только дополнение, не перезапись.
- [`../rules/schema.md`](../rules/schema.md) — фиксированная схема frontmatter.
- [`../rules/naming.md`](../rules/naming.md) — правила имён файлов.
- [`../rules/evidence.md`](../rules/evidence.md) — уровни уверенности.

## Алгоритм

### Шаг 1. Собрать контекст

1. Прочитай `Книги/<Название>/index.md` — узнай `read_through` и список уже известных сущностей (через ссылки или Dataview-запрос).
2. Прочитай заметки персонажей и мест, которые уже существуют, — чтобы не дублировать.
3. **Не** читай главы с номером > N.

### Шаг 2. Извлечь сущности из текста

Внутренне (не показывая пользователю) построй JSON-черновик:

```json
{
  "new_characters": [
    {"name": "Алиса", "aliases": ["Алиска"], "age": 7, "first_mention": "..."}
  ],
  "new_locations": [
    {"name": "Кроличья нора", "parent": null}
  ],
  "new_events": [
    {"title": "падение в нору", "order": 3, "participants": ["Алиса"], "location": "Кроличья нора", "summary": "...", "date": null}
  ],
  "new_relations": [
    {"from": "Алиса", "to": "Сестра Алисы", "type": "сестра", "confidence": "high"}
  ],
  "appearances": [
    {"character": "Алиса", "chapter": N}
  ]
}
```

Извлекай только то, что:

- **впервые упомянуто в этой главе**, или
- **обновилось** относительно существующих заметок (новая связь, новый возраст, новая роль).

### Шаг 3. Записать в vault

Для каждой сущности из черновика:

| Тип сущности | Действие |
|---|---|
| `new_characters` | если файла нет — создай по шаблону [`../templates/character.md`](../templates/character.md); если есть — обнови `appears_in`, `aliases`, добавь секцию `## Глава N` в тело |
| `new_locations` | аналогично, шаблон [`../templates/location.md`](../templates/location.md) |
| `new_events` | всегда создаёшь новый файл по [`../templates/event.md`](../templates/event.md), имя `E<NNN>-<кебаб>.md`, где `NNN` — глобальный счётчик событий в книге. Старайся выделять 1 главное событие в главе. В исключительных случаях 2-3. Обычно больше не надо|
| `new_relations` | дополняй массив `relations` в frontmatter персонажа **И** добавь inline-поле `тип :: [[Кому]]` в тело (для подписей в Extended Graph и Dataview). Применяй и обратную сторону, если связь симметричная (друг↔друг, брат↔сестра по контексту) |
| `appearances` | в персонаже/месте добавь главу в `appears_in`, если её там нет |

После — обнови заметку главы `Книги/<Название>/Главы/Глава-NN.md` по шаблону [`../templates/chapter.md`](../templates/chapter.md):

- заполни `new_characters`, `new_locations`, `new_events` ссылками;
- в теле — краткое (3–5 пунктов) резюме событий главы **без оценок и интерпретаций**.

В конце увеличь `read_through` в `index.md` до `N` (но **не** уменьшай, если уже было больше).

### Шаг 3.5. Обновить карту книги (`Карта.canvas`)

Цель — поддерживать в `Книги/<Название>/Карта.canvas` актуальный «скелет» сюжета без проходных событий.

1. Открой `Карта.canvas`, если он существует; иначе действуй по [`canvas-builder.md`](./canvas-builder.md) и создай его.
2. **Добавь новые узлы:**
   - всех новых `character` и `location`, появившихся в главе;
   - **только ключевые** события главы. Критерии «ключевого»:
     - `importance: критическая` (или эквивалент) в frontmatter события, **или**
     - событие меняет расстановку сил, отношения, статус героя или место действия для будущих глав.
   - Если в главе нет ключевых событий — не добавляй ни одного. Норма ~0–2 ключевых события на главу.
3. **Добавь новые рёбра:** связи между уже присутствующими и новыми узлами (см. `canvas-builder.md`, Шаг 1).
4. **Не удаляй** ранее добавленные узлы и рёбра — карта только растёт. Если связь устарела (например, друг → враг) — обнови `label` существующего ребра, не пересоздавай.
5. Сохрани координаты существующих узлов (см. `canvas-builder.md`, Шаг 3). Новые узлы клади в свободную зону (ниже/правее уже существующих) — человек подвинет руками.
6. В отчёте перечисли, какие узлы и рёбра добавлены/обновлены в `Карта.canvas`.

### Шаг 4. Отчёт пользователю

См. «Контракт ответа агента» в [`../../AGENTS.md`](../../AGENTS.md). Кратко:

- список созданных файлов;
- список обновлённых файлов с пометкой «что изменилось»;
- отдельно — связи и факты с `confidence: low` (требуют ревью).

**Не** показывать сырой JSON и **не** пересказывать главу в чате.

## Антипаттерны

- ❌ Создавать `event` без `chapter` и `location` (хотя бы `null`).
- ❌ Создавать связь `relation` сразу в обе стороны, если в тексте сказано только об одной (например, «А любит Б» ≠ «Б любит А»).
- ❌ Использовать общеизвестные факты о книге, которых нет в тексте главы.
- ❌ Перезаписывать существующий файл целиком.
