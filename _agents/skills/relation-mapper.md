# Skill: relation-mapper

Точечная работа со связями персонажей: добавить, изменить, удалить, нормализовать.

## Когда применять

- Пользователь говорит: «Добавь связь X — Y: брат».
- Пользователь правит фактическую ошибку: «Они не брат и сестра, а кузены».
- Нужно нормализовать словарь типов связей (привести «братец» и «брат» к одному).

## Правила

Сверься с [`../rules/schema.md`](../rules/schema.md) — раздел «Типы связей (контролируемый словарь)».

## Алгоритм

### Добавление связи

1. Открой `Персонажи/<X>.md`.
2. В frontmatter `relations` добавь:
   ```yaml
   - {to: "[[Y]]", type: <тип>, since: "[[Глава-NN]]", confidence: <high|medium|low>}
   ```
   `NN` = текущий `read_through` из `index.md` (или то, что назвал пользователь).
3. В теле — добавь inline-поле в секцию связей: `<тип> :: [[Y]]`.
4. Если связь **симметрична** (родственная того же уровня — брат/сестра, муж/жена, друг/друг), повтори в `Персонажи/<Y>.md` с правильным «зеркальным» типом:
   - брат↔сестра (с учётом пола), брат↔брат, муж↔жена и т.п.
5. Для **несимметричных** связей (отец/сын, учитель/ученик) — добавь обратную сторону с обратным типом.
6. Для односторонних чувств (`любит`, `боится`) — **не** добавляй обратную сторону без подтверждения в тексте.

### Изменение связи

- **Не редактируй** существующую запись, если она уже подтверждена `confidence: high` — создай новую с правильным типом и пометь старую `superseded_by: <новый-тип>`. Решение об удалении принимает человек.
- Если правка касается `confidence: low/medium` — можно редактировать на месте, но укажи `corrected_in: "[[Глава-NN]]"`.

### Удаление связи

Удалять связи может **только пользователь**. Агент может только пометить:
```yaml
- {to: "[[Y]]", type: брат, confidence: low, status: disputed}
```
и сообщить об этом в отчёте.

### Нормализация словаря

Если встретил тип связи не из контролируемого словаря:

1. Подбери ближайший из словаря.
2. Сохрани оригинальную формулировку в поле `raw_type` той же записи.
3. Сообщи об этом в отчёте — пользователь решит, дополнять ли словарь.

## Проверка после изменений

После любой правки `relations`:

- Inline-поле в теле заметки **должно** совпадать с frontmatter (источник истины — frontmatter, тело — для подписей рёбер в Extended Graph и для Dataview).
- Если у персонажа нет ни одной связи — это нормально, секция остаётся пустой.
- Не оставляй «висячих» ссылок: если ссылаешься на `[[Y]]`, заметка `Y.md` должна существовать (хотя бы как заготовка).
